# 管理后台

后台是游戏服务的一部分，入口为 `/werewolf/admin/`。默认关闭，启用后通过管理口令登录，无需用户名。

## 本机启用

先按 [README](../README.md)准备 `.env`。如果没有 `private-config.json`，复制配置模板：

```sh
cp deploy/config.example.json private-config.json
```

已有配置时保留原文件。然后生成管理凭证：

```sh
node tools/configure-admin.mjs http://127.0.0.1:8790
DEEPSEEK_ENV_FILE=.env npm start
```

配置工具将随机口令写入 `private-admin-access.txt`，只在终端打印保存路径；服务配置只保存摘要。两个私有文件都已排除在 Git 中，口令文件权限为 `0600`。服务已运行时需重启，配置才生效。

打开 [本机后台](http://127.0.0.1:8790/werewolf/admin/)，输入口令。地址必须与配置中的 Origin 一致，`localhost` 与 `127.0.0.1` 不可混用。

## 公网启用

用实际 HTTPS Origin 生成配置，例如：

```sh
node tools/configure-admin.mjs https://your-domain.example
```

Origin 不包含路径或末尾斜杠。工具始终修改工程根目录的 `private-config.json`；如果服务通过 `WEREWOLF_CONFIG` 使用另一份配置，需把生成的 `admin.origin` 和 `admin.tokenHash` 合并到实际服务配置，保留其余字段。管理口令文件留给管理者，不需要放入服务器或网页资源。

公网由反向代理提供 HTTPS，并保留 `Host`。后台使用固定 Origin 校验与 `Secure`、`HttpOnly`、`SameSite=Strict` 会话 Cookie；仅本机环回允许 HTTP。

## 可以看到什么

- **概览**：在线真人、AI 席位、房间数、连接数和离线暂停情况。
- **房间**：按房号搜索、按阶段筛选，查看公开席位、在线状态和朗读确认进度。
- **AI**：最近一小时调用量及上限、成功/失败/取消、正在处理的请求、平均耗时。
- **事件**：房间创建、人数变化、阶段切换、暂停恢复、AI 异常和管理员登录退出。

后台每 5 秒刷新，也支持手动刷新。页面隐藏时暂停轮询，返回后同步；网络失败会保留上次画面并标记过期，会话失效则返回登录页。

后台只读，不提供踢人或修改牌局。隐藏身份、私密线索、夜间行动对象、聊天正文、玩家 IP 和恢复凭证都不在管理数据中。

## 统计与会话

房间数只包含实际存在的桌子，不包含无人进入的虚拟公共大厅。AI 最近一小时用量按滚动窗口统计；成功、失败、取消和平均耗时从服务启动开始累计。平均耗时包含已结束的成功、失败及取消请求，模型超时算失败。这些是请求指标，不是费用账单。

服务保留最近 100 条事件，页面显示最近 40 条。房间、事件、累计指标和管理会话都保存在内存中，重启后清空；后台不提供历史归档或离线告警。

会话最长 8 小时，连续 30 分钟没有后台请求后过期；页面自动刷新算活跃请求。用完共享电脑请退出管理。登录限流按直接连接来源计算；位于同一反向代理后的登录通常共享每分钟 10 次尝试的限制。

## 轮换或关闭

配置工具拒绝覆盖现有口令。轮换时，先保留私有配置与口令的安全备份，移走旧 `private-admin-access.txt`，移除配置中的 `admin` 字段，再用正确 Origin 运行工具。把新摘要同步到服务配置并重启，旧会话随之失效。

只需从实际服务配置移除 `admin` 并重启，即可关闭后台。重启会结束内存中的牌局，操作前应安排好正在进行的游戏。
